# JARVIS（ジャービス）

声で話しかけて、PC上のAI（Kiro CLI / Claude Code / ChatGPT(Codex CLI)）に仕事をさせる音声AI執事。
[jarvis-build-guide](https://github.com/voixa/jarvis-build-guide) に着想を得て、その「録音→文字起こし→AI→読み上げ」「ハンズフリー」「HUD」「ウェイクワード」「安全第一」を、複数AI対応のWebアプリとして実装。

```
ブラウザ(React) ──/api──▶ backend(FastAPI+SQLite, Docker) ──HTTP+Token──▶ bridge(ホスト) ──▶ kiro-cli / claude / codex
   音声入力(Web Speech)        会話・タスク・ログをDB保存                   PCにログイン済みのCLIを実行
   音声出力(edge-tts等)
```

## 起動

```bash
./start.sh     # 初回は .env を自動生成。bridge をホストで起動し、Docker をビルド/起動
./stop.sh
```
ブラウザで http://localhost:3210 （Chrome / Edge / Safari 推奨。音声認識に必要）。
初回は **初期設定画面** で「既定のAI」と「読み上げの声」を選びます（後から設定画面で変更可）。

前提: Docker、python3、使いたいAI CLIが **PCでログイン済み**（`kiro-cli` / `claude` → `/login` / `codex login`）。

## 機能

- **AI選択**: 会話ごと・発言ごとに画面下のセレクトで切替。既定のAIは設定で変更。
- **会話の引き継ぎ**: 全発言を「どのAIが答えたか」付きでDBに保存。送信のたび、直近N件（既定20）の履歴を
  共通フォーマットでAIに渡すので、Kiroで話した続きをClaudeやChatGPTで再開できます。
- **速さ**: Kiro は常駐エージェント(ACP)で動かし、空のセッションを先に温めておくので、依頼から約2秒で返ります（従来は毎回CLIを起動して約6.5秒）。連続で依頼した時だけ、次のセッションの準備待ちで数秒遅れます。モデルを指定した時や常駐が使えない時は、従来のCLI起動に自動で切り替わります（`.env` の `BRIDGE_KIRO_ACP=0` で常駐を無効化）。声で頼んで返事が遅い時は、先に「はい、確認します」と一言返します。
- **短く答える**: personaで「基本1〜2文・60字以内、重要な時だけ長く」を指示。さらに読み上げは既定140字までで、超えた分は画面表示にします（確認・エラーは常に全文）。設定で変更可。
- **ハンズフリー画面**: ハンズフリー中は、チャットではなく「ジャービスが話している」専用画面（大きな球体＋今読んでいる文を強調した字幕）になります。💬ボタンでチャット画面に切替可。
- **アーカイブ**: 会話の📦でアーカイブ（一覧から消え、サイドバー下の「アーカイブ」欄へ。↩で復元）。アーカイブから**180日（約半年）で自動削除**（メッセージ・タスクログごと完全削除。1時間ごとに判定）。日数は設定で変更可。アーカイブ中の会話に発言すると自動で復元。
- **タスクログ**: 依頼ごとに1タスク。左メニュー「📋 タスクログ」で一覧、選ぶとリアルタイムでログ表示（ツール実行・stderr・結果）。中止も可能。
- **音声**: 🎤で押して話す／「ハンズフリー」で連続会話／ウェイクワード（既定「ジャービス」）／「バイバイ」で終了。
- **声の登録（話者認証）**: 設定→「声の登録」で自分の声を登録（5文を読む、3件以上）。ハンズフリー中は**登録した声の持ち主の発話だけ**を採用（音楽の歌声・テレビ・他の人を除外）。声紋モデル(3D-Speaker CAM++)はバックエンドのDockerに同梱、声紋データはPC内のDBにのみ保存。複数人の登録も可。🎤の押して話す時は既定で照合なし（設定で変更可）。設定の「照合テスト」で自分と他の人の点数を見て、しきい値を調整。
- **声**: edge-tts（無料・流暢な日本語: Nanami/Keita）が既定。**VOICEVOX**（Docker で自動起動・話者128種）、AivisSpeech（ローカル）、ブラウザ標準音声も選択可。設定画面で声・速さ・高さを調整でき、合成に失敗したらブラウザ標準音声へ自動フォールバック。
- 状態で色が変わるHUDリアクター（待機=青/聞取=緑/思考=橙/発話=脈動）。

## 安全設計

- bridge は既定 `127.0.0.1` バインド + Bearerトークン（`.env`、権限600）。Webは `127.0.0.1` のみ公開。
- **標準は「作成・編集は自動、削除とコマンド実行は毎回確認」**。仕組みで強制しています:
  1. 通常はAIを edit 権限で起動（Kiro: `--trust-tools=fs_read,fs_write` / Claude: `acceptEdits` + Bash禁止 / Codex: `workspace-write`）。削除・シェル実行はそもそも実行できない。
  2. AIが削除などを必要とすると、実行せず確認を返す → 画面に［許可して実行（今回だけ）］［やめる］が出て、読み上げもされる。声で「はい」「やめて」でも可。
  3. 許可された**その1回だけ** full で実行。次の依頼は元の確認ありに戻る。
- **全許可は「全部許可」とあなたが言った会話だけ**（文字でも音声でも）。画面上部に警告が出て、「許可を戻して」または［確認ありに戻す］で解除。他の会話には影響しません。AIの出力では切り替わりません。
- 設定画面で「読み取りのみ」や「常に全許可（非推奨）」にも変更可。この仕組みには `.env` の `BRIDGE_ALLOW_FULL=1`（標準）が必要。0にすると許可しても実行されません。
- 既知の制限: Codex の `workspace-write` は作業フォルダ内の削除をCLI側では防げないため、Codexでは確認ルール(指示)頼みです。
- AIの作業フォルダは `BRIDGE_WORKDIR`（既定 `~/jarvis-workspace`）。これは起動場所であって権限の境界ではありません。

## 補足

- Linux の Docker: `.env` で `BRIDGE_HOST=0.0.0.0` にする（トークン必須・外部に公開しないこと）。
- 音声認識（Web Speech API）はブラウザ提供元のサーバーで処理されます。完全ローカルにしたい場合は whisper 系STTへの差し替えが必要です。
- VOICEVOX: `.env` の `COMPOSE_PROFILES=voicevox` で公式エンジン(`voicevox/voicevox_engine:cpu-latest`)を一緒に起動（初回はイメージ取得に数分）。不要なら空欄に。PCにVOICEVOXアプリを入れる場合は、設定のURLを `http://host.docker.internal:50021` に。音声を公開する場合は「VOICEVOX:キャラ名」のクレジット表記が必要。
- AivisSpeech は https://aivis-project.com/ （既定ポート10101）。
- データ: `./data/jarvis.db`（SQLite）。ログ: `bridge/bridge.log`。
- 開発: `cd frontend && npm run dev`（backend は `localhost:8000` を想定）。
